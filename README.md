# BRIEF : Cadrer un service numérique pour une mise en œuvre responsable

Vous allez transformer les constats issus de votre première analyse ACV flash en une stratégie d’action concrète et priorisée, en préparant la future mise en œuvre sur un environnement technique représentatif.

À partir d’un service numérique réel choisi en début de formation, vous devrez :
- préciser le périmètre du projet,
- identifier les contraintes et objectifs,
- sélectionner des indicateurs environnementaux pertinents,
- prioriser des actions d’amélioration,
- puis relier ce diagnostic à un repo starter miroir correspondant à la catégorie de votre service.

Ce travail constitue le pont entre :
- le diagnostic initial,
- le plan d’action d’éco-conception,
- et les futures implémentations techniques mesurables.

## Contexte du projet

En tant que développeur, développeuse ou membre d’une équipe numérique engagée dans une démarche d’éco-conception, vous participez au cadrage d’un projet d’amélioration d’un service numérique existant.

Vous partez d’un cas réel déjà analysé lors du Brief #1 :

- unité fonctionnelle,
- composants mobilisés,
- mécanismes d’impact,
- premières bonnes pratiques prioritaires.
- Comme vous n’avez pas toujours la main sur le code du service analysé dans la réalité, vous devrez associer votre cas à un repo starter pédagogique représentant une famille de service comparable. Ce repo servira de terrain d’expérimentation pour les étapes suivantes.

Votre rôle est donc de :

- traduire les constats d’analyse en choix de cadrage ;
- relier les priorités environnementales à des actions techniques réalistes ;
- construire un backlog initial cohérent avec votre ACV flash ;
- préparer un plan d’action de mise en œuvre responsable sur 6 mois.
- Catégories de services / repos starters

Chaque apprenant ou groupe rattache son service réel à une seule des 4 catégories suivantes :

1. Site vitrine / média / institutionnel - Repo associé : heavy-showcase
2. E-commerce / catalogue / réservation - Repo associé : heavy-shop
3. Dashboard / outil métier / SaaS interne - Repo associé : heavy-ops
4. Plateforme de contenu / espace membre / LMS / portail - Repo associé : heavy-hub

## Modalités pédagogiques

- Travail individuel ou en binôme selon l’organisation choisie.
- FOAD possible pour affiner les livrables.
- Un repo starter miroir est fourni selon la catégorie choisie.
- Hotlines et support à distance disponibles.
- Présentation orale au J8, sous forme de pitch de 10 min maximum.
- Les livrables doivent montrer la cohérence entre :
1. le service réel analysé,
2.  les constats ACV,
3. le repo miroir,
4. et les actions priorisées.

## Modalités d'évaluation

- Évaluation par le formateur via checklist des livrables
- Commits clairs sur Git
- Présentation orale
- KPI + feedback structuré

## Livrables

1. Cartographie de cadrage du projet
2.	Slides de plan d'action sur 6 mois + contenus slides précédentes. 
3. Fichier excel d'analyse EcoIndex.
4. Un fichier backlog.md contenant au minimum 3 user stories, chacune avec :
- contexte : En tant que… je veux… afin de… ;
- objectif (qualitatif ou chiffré) ;
- 1 bonne pratique d’éco-conception ciblée ;
- 1 KPI associé ;
- repo ou écran concerné ;
- critère de réussite ;
- niveau de priorité.
5. Lien vers le dépôt Git

## Critères de performance

- Tous les livrables sont présents, cohérents et exploitables.
- Le service réel, la catégorie choisie et le repo associé sont clairement reliés.
- Les données EcoIndex ou de baseline sont concrètes, lisibles et utiles pour décider.
- Le plan d’action est cohérent avec l’ACV flash, l’UF et les priorités identifiées.
- La roadmap présente un effort / résultat réaliste.
- Le backlog est structuré et directement réutilisable pour la suite.
- Les KPI choisis sont compréhensibles, pertinents et liés aux objectifs.
- Le dépôt Git est identifiable, clair et traçable.
- La présentation orale est courte, claire et comprise.
